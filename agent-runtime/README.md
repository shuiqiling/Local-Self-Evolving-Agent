# 水麒麟：Ubuntu 统一记忆与工具 Agent

截至 **2026-11-01**，正式实验链路是 **Qwen3-30B-A3B Q4_K_M＋主 LoRA**，主聊天、记忆利用、网页查询和工具开发由同一个决策 Agent 完成。独立 R17 辅助 LoRA 只做经历证据整理，与主适配器分开选择，共用基础权重。

## 运行结构

| 服务 | 职责 |

| `lea-shuiqilin`，18815 | 统一 Agent、记忆、任务、工具、独立状态入口 |
| `lea-qwen30b-trial`，18813 | llama.cpp 30B 推理；主／辅助适配器分别启用 |

后端上下文上限 8192 tokens，当前工作预算 4096。主 Agent 使用轻量思考；辅助整理关闭思考。状态入口在上一轮完成后等待 10 秒再尝试，因此不是每 10 秒保证完成一次推理。CPU 温度、流量、内存等记录明确属于宿主机观测；接口流量不代表可用网速。

旧 4B 与旧原生 KV 链路已暂停并屏蔽自动启动。仓库中的 `deployment/kv_service/` 和 Fast KVzip 代码作为历史实验保留。

## 记忆与切窗

原始记录向量检索和关键词检索并行，轻量规则重排；摘要用于导航，按需读取原文。原始事件、时间、角色和操作回执持久化，记忆存储硬上限为 **10 GiB**。相关性门槛仍是待独立校准的工程参数。

当前采用 `source-checkpoint-v1 / r1-guarded-sources`：切窗提交原始事件与真实操作账本的检查点，不调用模型另写交接文档。视图保留当前请求及条件，区分宿主机状态与任务对象，使用实际 tokenizer 缩减可选历史。`context.read` 可按任务内引用分页找回原文。

这不是当前对 30B 做 Fast KVzip 压缩。必须保留的请求、状态和回执本身仍可能超过工作预算；小说阅读器任务已实际触发 `BudgetExceeded`，该问题尚未修复。

## 自动 LoRA

1. 每累计 10 次真实提交的切窗，冻结一批来源记录；没有每日一次限制。
2. 先过滤没有完整训练证据的片段。普通状态数值保留在记忆中，不反复作为新目标或旧样本回放训练。
3. R17 辅助适配器选择补充证据；程序固定保留真实回执与先前条件。未经验证的影响保持未知，不生成原因、建议或成功结论供模型模仿。
4. 来源校验后产生短事实回答或已验证操作样本。动作输入不能泄漏执行后的结果；失败测试回执可以作为事实保留，未经验证的修复不能当作正确行为。
5. 有合格新样本时执行 CPU NF4 QLoRA：FP32 计算，rank8 的 q_proj/v_proj，最多 8 个优化步，学习率不高于 5e-6，单序列不超过 512 tokens。
6. 新适配器成功加载后，清理旧 KV，再恢复下一窗口推理。空批次、训练失败不触发这次 KV 清理。

8 个优化步不是固定的总训练时长：梯度累积会随样本数增加。新权重当前采用 **loadability_only** 上线策略，未做模型能力回归验收。来源真实、格式正确、权重能加载，都不能单独证明模型能力提升。

新版上线后已自然处理一批 10 窗口、137 条来源记录：调用辅助模型一次，整理 14.024 秒；最终没有合格新样本，完整执行跳过分支，没有梯度训练或权重切换。

## 网页与工具开发

`web.search(query)` 返回候选；`web.next_page(cursor)` 读取后续候选；`web.open(url)` 获取可访问网页正文。搜索结果不表示已经读过正文；不可达或验证页不能报告为成功读取。

水麒麟通过 `dev.submit → dev.test → dev.publish → dev.run` 自行编写并使用工具。独立验收用例在实现前冻结，测试绑定当前代码版本。执行器只允许运行受限纯 Python，文件读写通过现有工作区接口完成；它不是可任意操作宿主系统的终端。

小说阅读器目前只完成第一版 `novel_page` 的提交和测试。`next_offset` 没有在末尾限制到文本长度，自测通过 1/3、独立验收通过 4/9；随后因必要上下文超预算而停止。尚未修复、登记，也没有完成保存进度、恢复续读和长文件读取演示。当前要求是只观察，未发送续跑指令。
