# 水麒麟：Ubuntu 统一记忆与工具 Agent

截至 **2026-11-02**，正式实验链路是 **Qwen3-30B-A3B Q4_K_M＋主 LoRA**，主聊天、记忆利用、网页查询和工具开发由同一个决策 Agent 完成。独立 R17 辅助 LoRA 负责经历证据整理和原文导航索引，与主适配器分开选择，共用基础权重。

## 记忆与切窗

由主 Agent 按需发起记忆查询，原始记录向量检索和关键词检索并行，轻量规则重排；摘要用于导航，按需读取原文。原始事件、时间、角色和操作回执持久化，记忆存储硬上限为 **10 GiB**。相关性门槛仍是待独立校准的工程参数。

2026-11-02 已部署[主动分页记忆](deployment/shuiqilin/20261102/runtime/active_memory.py)：`memory.search(query)` 每批最多三条索引，`memory.next(cursor)` 查看下一批，`memory.read(index_id, query)` 仅在选中来源内找细节。取消自动历史索引及重复状态注入，保留当前要求、约束与最近真实回执，完整原文仍在档案。同一冻结请求输入 4072→1548 tokens，工作余量 24→2548；最终线上请求输入 1967、余量 2129。29 项检查及真实模型查询／翻页／读原文流程通过。部署后六次自然状态推理约 50～61 秒，没有预算超限；仍有重复读笔记和被拒绝的写入，不能当成新的开发进展。这些结果不证明底层 TPS 或通用记忆准确率提高，见[实机验证](validation/shuiqilin-progress-20261102.json)。

2026-11-01 新增[辅助记忆索引](deployment/shuiqilin/20261102/runtime/navigation_runtime.py)：R17 辅助 LoRA 在后台选择长文本关键原句，程序保留条件、更正和来源；在线短记录完整保留，工具回执投影真实字段。索引不等待训练周期。原文召回后默认仅显示去重导航，取消自动附带原文证据，需要细节时再读档。超长或待处理来源使用明确标记的不完整预览。验收摘要见[索引验证](validation/shuiqilin-progress-20261102.json)。同日已将三套库的全部历史检索来源交给辅助模型处理：329 份去重原文、1,025 条来源记录、3,689 个检索片段，零失败、原文未改动，耗时约 15 分 28 秒；见[历史回填验收](validation/shuiqilin-progress-20261102.json)。后续新增记录继续按在线策略处理。

当前采用 `source-checkpoint-v1 / r1-guarded-sources`：切窗提交原始事件与真实操作账本的检查点，不调用模型另写交接文档。视图保留当前请求及条件，区分宿主机状态与任务对象，使用实际 tokenizer 缩减可选历史。`context.read` 可按任务内引用分页找回原文。

这不是当前对 30B 做 Fast KVzip 压缩。[执行轨迹优化](deployment/shuiqilin/20261102/runtime/trace_view.py)将旧代码和旧回执按来源引用展示，最新回执和用户约束保持原文。后续发现原回放未包含完整开发环境与模型额外提示，不能据此断定实际请求已进入预算。此次[执行恢复优化](deployment/shuiqilin/20261102/runtime/execution_recovery.py)按真实开发链路重放：旧版实际 4,380 tokens，新版 4,035，预检查与发送内容一致。生产续跑也已成功使用超过 4,096 的临时输入预算。

执行每 16 步保存断点，有新增操作进展时自动续接同一作业；累计 64 步或连续无进展时明确暂停，可从界面“从断点继续”。结构化输出截断时只重试模型生成一次，768→1536 tokens，不执行截断内容。真正超过后端安全余量的请求仍会暂停并保留原文，不无限重试。

同日进一步部署[读取与重复操作修复](deployment/shuiqilin/20261102/runtime/receipt_reporting.py)：文件更新后重新读取当前内容，避免命中旧回执；明确的单次工具请求在真实调用结束后转入报告，防止重复写入。健康检查复用一次适配器探测，超时返回未就绪而不是 HTTP 500。已验证发布工具的源码按引用读取，实际工具视图由 856 降至 785 tokens；这不是新的 TPS 测试。本地 94 项回归、Ubuntu 22 项新增测试通过，最新线上核验见[验证记录](validation/shuiqilin-progress-20261102.json)。

2026-11-02 部署[回执报告优化](deployment/shuiqilin/20261102/runtime/receipt_reporting.py)：可识别的明确单次请求在执行前后使用同一份精简工具说明；重复写入被去重时另行核对当前文件文本，区分历史成功与当前状态。LoRA 成功或正常跳过后，后台状态调用等待批次游标确认完成再恢复，修复收尾阶段抢锁。后续还修复了“不要重新开发”被误判为开发任务、绕过单次调用限制的问题。真实答复上下文回放 4,478→4,206 tokens；一次冷输入处理对照为 61.27→59.41 秒，不能据此宣称持续 TPS 提升。114 项本地回归和 20 项 Ubuntu 新增测试通过；详见[最新验证](validation/shuiqilin-progress-20261102.json)。

同日进一步部署[写入读回与程序回执](deployment/shuiqilin/20261102/runtime/write_receipts.py)：写入回执附带有界的实际正文；可确定解析的单次请求将文件名和“原样写入”的文字绑定到 schema 及执行校验，防止擅自换名或改字。明确只写一次并报告回执时，程序直接核对文件并报告，标明内容尚未验收；分析、解释等请求仍交给模型。最终真机请求只调用一次模型，耗时 34.98 秒，写后报告 0.672 秒；同一请求的旧版成功留存记录为两次调用、80.61 秒、写后报告 39.22 秒。两次运行不相邻，不代表持续 TPS 提升。138 项本地回归、8 个子案例和 24 项 Ubuntu 测试通过；三次未通过验收的过程均保留。最新结果见[写入核验记录](validation/shuiqilin-progress-20261102.json)。

旧 4B／KV 服务仍永久暂停。对其中 8 组完全相同的冷快照做可恢复的只读文件去重，保留原路径和内容，释放约 **1.82 GiB**；记忆卷的 **10 GiB** 上限不变。

## 自动 LoRA

1. 每累计 10 次真实提交的切窗，冻结一批来源记录；没有每日一次限制。
2. 先过滤没有完整训练证据的片段。普通状态数值保留在记忆中，不反复作为新目标或旧样本回放训练。
3. R17 辅助适配器选择补充证据；程序固定保留真实回执与先前条件。未经验证的影响保持未知，不生成原因、建议或成功结论供模型模仿。
4. 来源校验后产生短事实回答或已验证操作样本。动作输入不能泄漏执行后的结果；失败测试回执可以作为事实保留，未经验证的修复不能当作正确行为。
5. 有合格新样本时执行 CPU NF4 QLoRA：FP32 计算，rank8 的 q_proj/v_proj，最多 8 个优化步，学习率不高于 5e-6，单序列不超过 512 tokens。
6. 新适配器成功加载后，清理旧 KV，再恢复下一窗口推理。空批次、训练失败不触发这次 KV 清理。

8 个优化步不是固定的总训练时长：梯度累积会随样本数增加。新权重当前采用 **loadability_only** 上线策略，未做模型能力回归验收。来源真实、格式正确、权重能加载，都不能单独证明模型能力提升。

新版上线后已自然处理一批 10 窗口、137 条来源记录：调用辅助模型一次，整理 14.024 秒；最终没有合格新样本，完整执行跳过分支，没有梯度训练或权重切换。

## 网页与工具开发

`web.search(query)` 返回候选；`web.next_page(cursor)` 读取后续候选；`web.open(url)` 获取可访问网页正文。搜索结果不表示已经读过正文；不可达或验证页不能报告为成功读取。

水麒麟通过 `dev.submit → dev.test → dev.publish → dev.run` 自行编写并使用工具。独立验收用例在实现前冻结，测试绑定当前代码版本。执行器只允许运行受限纯 Python，文件读写通过现有工作区接口完成；它不是可任意操作宿主系统的终端。

小说阅读器已获用户授权续跑。水麒麟自行修复了 `next_offset` 越过末尾的问题，新版 `rev_dfda6ae06c8b4bdf` 自测 3/3、独立验收 9/9，通过后已登记。现已核对同一文本的三页真实调用：位置 0→4→8→12、正文连续无重复；进度 8 已真实保存并读回，续读返回最后四字符且 `done=true`。保存作业曾重复写入至暂停，运行时修复后从同一作业恢复完成，没有新增写入。使用说明已写入，但有界修正仍遗漏读回实测、允许目录及 UTF-8 边界等必要条件，文档内容验收未通过；单次写入成功不能代替内容正确。当前工具接收字符串，尚未实现宿主长 TXT 文件读取接口。上述演示有逐步引导，不能宣称无人引导自主完成。最新结果见[运行时与真实回执验证](validation/shuiqilin-progress-20261102.json)，早期过程见[执行恢复验收](validation/shuiqilin-progress-20261102.json)。
